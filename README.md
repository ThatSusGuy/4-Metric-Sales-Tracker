# 4-Metric Sales Tracker

A tiny dashboard that pulls 4 weekday-only sales metrics from a Notion database and displays them on a static page hosted on GitHub Pages.

## The 4 metrics

All metrics ignore weekends. "This week" = Mon–Fri of the current calendar week in your configured timezone.

1. **Current Streak** — consecutive weekdays where `Calls Converted ≥ 2`. Record line shows the longest run ever.
2. **Top Contract Value (this week)** — `max(Contract Value)` across this week's weekdays. Record line shows the highest `Contract Value` ever and the date.
3. **Top Cash Collected (this week)** — `max(Cash Collected)` across this week's weekdays. Record line shows the highest `Cash Collected` ever and the date.
4. **Close Rate (this week)** — `sum(Calls Closed) / sum(GP Call (only final))` across this week's weekdays. Record line shows the best weekly close rate ever (weeks with no GP calls are skipped).

## Architecture

```
Notion DB  →  n8n (Schedule → Notion → Code → GitHub)  →  data.json in this repo  →  GitHub Pages serves index.html
```

- `index.html` — static dashboard, dark theme, fetches `data.json` with cache-busting on every load.
- `data.json` — generated by n8n, committed to this repo on every run.
- `n8n-workflow.json` — importable workflow with the metric calculations.

No browser-side secrets. The Notion API key only lives inside n8n.

## Setup

### 1. Turn on GitHub Pages

Repo **Settings → Pages**:

- **Source**: Deploy from a branch
- **Branch**: `main` / `(root)`

Once enabled, the page will live at `https://thatsusguy.github.io/4-metric-sales-tracker/`.

### 2. Share the Notion database with an integration

1. Notion → **Settings → Connections → Develop or manage integrations → New integration** → name it (e.g. "Sales Tracker"), copy the **Internal Integration Token**.
2. Open your sales-tracker database in Notion → top-right `…` → **Connections → Add** → select your new integration.
3. Copy the database ID. Easiest way: open the DB as a full page, the URL looks like `https://www.notion.so/<workspace>/<32-char-id>?v=…` — the 32-char chunk is the database ID.

### 3. Import the n8n workflow

1. n8n → **Workflows → Import from File** → upload `n8n-workflow.json`.
2. **Credentials**:
   - **Notion account** — paste the Internal Integration Token.
   - **GitHub PAT** — create a fine-grained personal access token at https://github.com/settings/personal-access-tokens/new with:
     - **Repository access**: only `thatsusguy/4-metric-sales-tracker`
     - **Repository permissions**: **Contents → Read and write**
3. In the **Notion — get all rows** node, paste your database ID.
4. In the **Compute metrics** node, edit the first line and set `TZ` to your IANA timezone (e.g. `"America/New_York"`, `"Europe/London"`, `"Asia/Singapore"`).
5. In the **Commit data.json** node, confirm `owner`, `repository`, and `branch` match your repo.
6. **Activate** the workflow. It runs hourly; change the Schedule node if you want a different cadence.

### 4. Verify

1. Click **Execute Workflow** in n8n once manually.
2. Check the repo — `data.json` should be updated with a new commit.
3. Open the GitHub Pages URL — the 4 cards should populate.

## Notion property names this expects

These names are hardcoded in the Code node. If your DB uses different names, edit the `num(p, "...")` calls in the **Compute metrics** node.

| Property | Type | Used for |
|---|---|---|
| `Date` | Date | Row date |
| `Calls Converted` | Number | Streak |
| `Contract Value` | Number | Top CV this week + record |
| `Cash Collected` | Number | Top CC this week + record |
| `GP Call (only final)` | Number | Close rate denominator |
| `Calls Closed` | Number | Close rate numerator |

The `Contract Value 2/3/4` and `Cash Collected 2/3/4` columns aren't read — the daily "biggest deal" already lives in `Contract Value` / `Cash Collected`, which is what the weekly maximum needs.

## Local preview

`index.html` is a single file. Open it directly in a browser, or serve the folder:

```
python3 -m http.server 8000
# visit http://localhost:8000
```

It will display whatever is currently in `data.json`.
